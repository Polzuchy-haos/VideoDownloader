# Video Download

Расширение для **Firefox** и **Google Chrome**. Перехватывает видеопотоки из плееров **Kodik**,
**Alloha** и **CVH** (и вообще любых плееров на HLS/MP4) на сайте yummyani и позволяет их скачать.

## Готовые сборки

Сборки лежат в папке `dist/`. Если её нет или вы меняли код, соберите заново:

```
node tools/build.js
```

| Файл / папка | Для чего |
|---|---|
| `dist/chrome/` | Chrome: «Загрузить распакованное расширение» |
| `dist/dreamcast-downloadex-<версия>-chrome.zip` | Chrome: архив той же сборки |
| `dist/firefox/` | Firefox: временная установка |
| `dist/dreamcast-downloadex-<версия>-firefox.xpi` | Firefox: архив для подписи/постоянной установки |

## Установка

### Google Chrome (и Edge, Яндекс Браузер, Opera — любые на Chromium 116+)

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика» (переключатель справа вверху).
3. Нажмите «Загрузить распакованное расширение» и выберите папку `dist/chrome`.

Расширение остаётся установленным после перезапуска браузера. Папку `dist/chrome` после
установки не удаляйте и не перемещайте: Chrome загружает расширение прямо из неё.

### Firefox

**Временно** (до закрытия браузера): откройте `about:debugging#/runtime/this-firefox` →
«Загрузить временное дополнение…» и выберите `manifest.json` в корне проекта или в `dist/firefox`.

**Постоянно:** обычный Firefox устанавливает только подписанные дополнения.
- Подпишите `.xpi` на AMO как «unlisted» (самостоятельное распространение, без публикации в каталоге):
  `npx web-ext sign --channel=unlisted --source-dir dist/firefox --api-key=... --api-secret=...`.
  Ключи выдаются на addons.mozilla.org → «Инструменты» → «Управление ключами API».
- Либо используйте Firefox Developer Edition / Nightly / ESR с `xpinstall.signatures.required = false`
  в `about:config` и установите `dist/dreamcast-downloadex-<версия>-firefox.xpi`.

## Использование

### Быстрый способ: выбор плеера

1. На странице аниме нажмите иконку расширения, затем **«🎯 Выбрать плеер на странице»**.
   То же делает горячая клавиша **Alt+Shift+D**. Сменить её можно здесь:
   Chrome — `chrome://extensions/shortcuts`, Firefox — `about:addons` → ⚙ → «Управление горячими клавишами».
2. Наведите курсор на плеер (он подсветится) и кликните. Esc отменяет выбор.
3. Справа появится панель **только с видео этого плеера**. Лучший вариант отмечен
   «Рекомендуется», остальные свёрнуты в «Другие варианты».
4. Если панель пустая, нажмите Play в плеере: ссылка появится автоматически.

Панель можно перетаскивать за заголовок. Если на сайте сменить плеер или озвучку,
панель предложит выбрать плеер заново.

Как выбирается «лучший» вариант: сначала то, что плеер запрашивал последним, а в этой группе
прямой MP4 (Kodik), затем master-плейлист HLS, затем HLS, затем остальное. При равенстве выигрывает
более высокое качество. Варианты качества, которые уже входят в найденный master-плейлист,
считаются дублями и скрываются.

### Полный список

Иконка расширения показывает все видео, найденные на вкладке. На значке иконки виден их счётчик.
Для HLS можно выбрать качество и аудиодорожку, поправить имя файла и нажать «Скачать».

## Как это работает

- **Перехват запросов.** `webRequest` отслеживает запросы всех фреймов вкладки, включая
  iframe плееров. Видео распознаётся по адресу (`.m3u8`, `.mpd`, `.mp4`,
  Kodik `…:hls:manifest.m3u8`) и по `Content-Type`.
- **Глубокий анализ ответов.** На вкладках yummyani и в фреймах известных плееров расширение
  читает ответы API плееров. Так находятся ссылки, которых нет в адресах запросов:
  - закодированные ссылки Kodik (base64 + сдвиг Цезаря);
  - поля `hlsUrl` / `mpegHighUrl` у CVH;
  - конфиги Playerjs `[720p]https://…`;
  - m3u8 без расширения.

  Firefox читает тела ответов через `filterResponseData`. В Chrome такого API нет, поэтому
  `content/hook.js` перехватывает `fetch`/`XHR` прямо в странице плеера.
- **Подмена заголовков.** При скачивании подставляются `Referer`/`Origin` исходного запроса
  плеера, иначе CDN обычно отвечает 403. Firefox делает это блокирующим `onBeforeSendHeaders`,
  Chrome — сессионными правилами `declarativeNetRequest`.
- **Загрузка HLS.** Сегменты качаются параллельно, с повторами при ошибках. Поддерживаются
  AES-128, fMP4 (`EXT-X-MAP`) и byte-range, мусор перед замаскированными TS-сегментами
  отрезается. Потом сегменты склеиваются и сохраняются через загрузки браузера. В Chrome
  этим занимается offscreen-документ, потому что service worker не умеет создавать blob-ссылки
  и засыпает.
- **Прямой MP4.** Firefox отдаёт файл штатному загрузчику. В Chrome правила
  `declarativeNetRequest` не действуют на `chrome.downloads`, поэтому файл качается через
  `fetch` с докачкой по Range.
- **Выбор плеера.** Каждый поток привязан к iframe верхнего уровня, из которого он пришёл.
  Firefox определяет фрейм выбранного элемента через `runtime.getFrameId`, Chrome — через
  ответ content-скрипта внутри iframe.

Перечень доменов плееров находится в [lib/players.js](lib/players.js), список сайтов для
глубокого анализа — в `SITES_RE` в [background.js](background.js) и в
[content/hook.js](content/hook.js). Если плеер сменил домен, допишите его туда. Глубокий анализ
можно включить и для всех сайтов в настройках popup.

## Структура

```
background.js          фон: перехват, ранжирование, загрузки (Firefox — страница, Chrome — service worker)
lib/compat.js          общий слой browser.* / chrome.*
lib/engine.js          загрузчик HLS и прямых файлов
lib/m3u8.js            парсер плейлистов
lib/players.js         определение плеера, декодирование ссылок
content/picker.js      режим выбора плеера и панель на странице
content/relay.js       ответ на «пинг» выбора фрейма, передача перехваченных ответов (оба браузера)
content/hook.js        перехват fetch/XHR в странице плеера (только Chrome)
offscreen/             загрузчик для Chrome
popup/                 окно расширения
manifest.json          манифест Firefox (MV2)
platform/chrome/       манифест Chrome (MV3)
tools/build.js         сборка dist/ для обоих браузеров
tools/make-icons.js    генерация PNG-иконок
```

Версия берётся из корневого `manifest.json` и при сборке подставляется в обе сборки.

## Форматы и ffmpeg

HLS сохраняется как есть: `.ts` (MPEG-TS) или `.mp4` (fMP4). `.ts` открывается в VLC/MPC.
Конвертировать в MP4 без перекодирования:

```
ffmpeg -i "file.ts" -c copy "file.mp4"
```

Если плеер отдаёт звук отдельной дорожкой (часто так бывает у Alloha с несколькими
озвучками), сохраняются два файла, `*.video.ts` и `*.audio.ts`. Склеить их:

```
ffmpeg -i "file.video.ts" -i "file.audio.ts" -map 0:v -map 1:a -c copy "file.mp4"
```

## Ограничения

- DASH (`.mpd`) и DRM (SAMPLE-AES, Widevine) не поддерживаются.
- HLS-серия, а в Chrome и прямой MP4, собирается в памяти перед сохранением. На эпизод
  в 1080p нужно несколько сотен МБ RAM.
- Ссылки плееров временные и привязаны к IP. Если загрузка падает с 403, перезапустите
  воспроизведение, нажмите «Очистить» и возьмите свежую ссылку.
- Правила подмены заголовков действуют на весь хост. Если два плеера берут видео с одного
  CDN, но требуют разный `Referer`, работает последний выбранный. На практике такое бывает редко.
